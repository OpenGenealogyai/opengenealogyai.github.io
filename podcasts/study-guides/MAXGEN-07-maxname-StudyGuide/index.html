MaxName: A Comprehensive Study Guide to the Genealogical Name Variant Standard

This study guide provides a detailed overview of the MaxName standard, an open, structured format designed to solve the "name problem" in historical and genealogical research. It covers core concepts, architectural improvements, and the specific data structures used to capture name complexity across languages, time, and geography.

I. Key Concepts and Core Themes

The "Name Problem" in Genealogy

The "name problem" refers to the difficulty of identifying a single individual or family across historical records due to inconsistent naming conventions. The problem manifests in four primary ways: * Spelling Variants: Different clerks using different conventions for the same name (e.g., Maxwell vs. Makeswell). * Anglicization/Linguistic Adaptation: The transformation of names across languages (e.g., Gaelic Màiri becoming Mary; German Müller becoming Miller). * Scribal Error: Mistakes made by census takers or tax collectors based on phonetics or misunderstood scripts (e.g., omitting an umlaut or misinterpreting a regional accent). * Translation/Cognates: Equivalent names adapted to different linguistic communities (e.g., John, Johann, Ivan, and Seán).

The Research Gap

Existing standards fail to address the complexity of genealogical names. The following table summarizes why previous tools were insufficient for the needs of the MaxName standard:

Standard/Tool Limitation for MaxName Purposes
GEDCOM X Lacks a typed name variant structure.
WeRelate A wiki-based system without a machine-readable schema.
Behind the Name Proprietary and lacks provenance for cognate relationships.
JRC-Names Designed for news entity extraction, not historical genealogy.
LCNAF / VIAF Focused on modern library cataloging rather than historical variants.
HistNorm An academic NLP tool, not a standardized data format.

The Three-Brain Council Improvements

To ensure the schema was robust, it was reviewed by a "three-brain council" representing different perspectives: Engineer (Grok-3), Contrarian (qwen3:14b), and Operator (Claude). Key improvements included: 1. URI-Extensible Variant Types: Moving from a closed list to an open system using URIs to prevent schema "ossification." 2. Variant IDs: Assigning a UUID to every variant entry to make them independently addressable and citable. 3. Disputed Variants: Allowing multiple scholarly views to coexist through a disputed_by[] array. 4. Cognate Direction: Adding specific directions (source, derivative, or parallel) to name relationships.

II. Short-Answer Practice Questions

1. What is the function of the canonical_form in a MaxName record? The canonical_form serves as the anchor of the record, typically representing the modern authoritative spelling or the most common current spelling used as a reference point for all variants.

2. How does the regional_canonical[] array differ from the canonical_form? The regional_canonical[] array holds language-specific preferred forms for communities where the primary canonical_form is not the local preference. It ensures that no single language is treated as more "real" than others.

3. What are the four frequency enums used to describe name variants? * Rare: Under 5% of occurrences. * Occasional: 5–25% of occurrences. * Common: 25–60% of occurrences. * Dominant: Over 60% of occurrences.

4. Why does MaxName store the algorithm_version within the phonetic_keys{} object? Storing the version prevents silent future mismatches. Phonetic algorithms can change over time; by recording the version (e.g., the 1918 Soundex algorithm vs. a 2040 revision), future researchers can reconcile data accurately.

5. What is the requirement for attestation_source on cognate links? The attestation_source is a required citation—such as a dictionary or etymological study—that provides scholarly evidence for the claim that two names are cognates. Without it, the claim is considered an undocumented assertion.

IV. Comprehensive Glossary of Terms

Genealogical and Technical Terms

Term Definition
Anglicization The process of adapting a non-English name into English (e.g., Ó Briain to O'Brien).
Attestation The evidence or documentation provided to prove the existence of a name variant or relationship.
Cognate Names in different languages that share a common etymological origin (e.g., John and Johann).
Etymological Root The original source or linguistic origin of a name (e.g., Maccus for the name Maxwell).
Machine-Readable Data formatted so that it can be processed and understood by a computer system.
Normalization The process of grouping name variants under a single standard or canonical form.
OCR/NLP Optical Character Recognition and Natural Language Processing; technologies used to extract names from historical documents.
Provenance The record of ownership or the documented history of a piece of data, including its source and contributors.
Scribal Corruption An error in a name caused by a clerk mishearing or miswriting the original form.
UUID Universally Unique Identifier; a unique string used to identify a specific record or variant independently.

MaxName Schema Fields and Enums

Field/Value Description
canonical_form The modern, authoritative reference spelling for a name.
cognates[] An array linking the current name record to equivalent names in other languages.
disputed_by[] An array of records citing sources that contest the validity or equivalence of a name variant.
frequency An enum (Rare, Occasional, Common, Dominant) indicating how often a variant appeared in a specific time/place.
language_of_origin The linguistic source of the name (e.g., "non" for Old Norse).
name_type The category of the name (e.g., surname, given name).
phonetic_keys{} An object containing pre-computed phonetic codes for fuzzy searching.
regional_canonical[] Language-specific preferred forms of a name for different linguistic communities.
this_derives_from A cognate direction indicating the current name is a derivative of another.
this_is_source_of A cognate direction indicating the current name is the origin of another.
variant_id A UUID assigned to each individual entry in the variants array.
variant_type A string or URI defining the nature of the variation (e.g., nickname, latinization, legal_substitution).
variants[] A collection of all known historical forms of the name, including their scope and period.

Phonetic Algorithms

Algorithm Focus/Application
Beider-Morse A highly sophisticated algorithm designed for genealogical use across multiple European language families.
Daitch-Mokotoff Designed for Central and Eastern European Jewish names; handles complex branching phonetics.
Double Metaphone Generates primary and secondary phonetic codes for improved accuracy in matching.
Metaphone A phonetic algorithm for indexing names by sound.
NYSIIS New York State Identification and Intelligence System; optimized for English surnames.
Soundex The oldest phonetic algorithm, used primarily for English names but considered weak for non-English variants.
