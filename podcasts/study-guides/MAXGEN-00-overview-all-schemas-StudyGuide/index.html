The MAXGEN Standard: A Comprehensive Study Guide

This study guide provides a detailed overview of the MAXGEN v1.11 standard, an open-source genealogical data framework designed by OpenGenealogyAI. It explores the shift from traditional, siloed data models to a probabilistic, interoperable language designed for the era of artificial intelligence and distributed research.

Section 1: Short-Answer Practice Questions

1. What is the primary limitation of the original GEDCOM format as identified in the MAXGEN documentation? The GEDCOM format, designed in 1984, was built for families and basic exports but lacks the capability to handle the probabilistic, multi-source requirements of modern genealogy or represent uncertainty effectively.

2. Identify the seven schemas that comprise MAXGEN v1.11. The seven schemas are: * MaxRecord * MaxPerson * MaxTask * MaxDNA * MaxSource * MaxRecognition * MaxName

3. Explain the "Separation of Evidence and Interpretation" philosophy. MAXGEN distinguishes between what a document says (evidence) and what a researcher thinks it means (interpretation). Evidence is stored in the MaxRecord layer (uninterpreted), while the identity and biographical claims derived from that evidence are stored in the MaxPerson layer.

4. How does the MAXGEN confidence scoring system function? Every assertion carries a score from 0.0 to 1.0. * 0.95+: Documented certainty. * 0.7–0.95: Well-attested with some ambiguity. * 0.5–0.7: Plausible but requiring more evidence. * Below 0.5: Speculative.

5. What is the purpose of the ruled_out verdict in the MaxTask schema? The ruled_out verdict represents a definitive disproof. It is considered a "key finding" because proving that a specific record does not belong to an individual is as genealogically significant as proving it does.

6. How does MAXGEN ensure privacy for DNA data? MaxDNA maintains strict privacy by never storing raw genotype data. It hashes kit identifiers using HMAC-SHA-256 and mandates that every record is "tier2-private," regardless of other settings.

7. Describe the function of the embedding_text field in MaxSource. The embedding_text field is designed for use in vector databases. It allows researchers to perform semantic searches (e.g., "where find records for a Lutheran family in Württemberg in the 1840s?") and receive results rapidly.

8. How does the MaxRecognition schema handle multiple transcriptions of the same image? Multiple independent transcriptions are linked via a consensus_group_id. This allows an engine to compute aggregate confidence; for example, if five independent transcriptions agree on a name, the confidence score increases.

9. What is the "escape hatch" in MAXGEN schemas for system-specific data? Every schema includes an extensions{} object with additionalProperties: true. This allows organizations to add custom fields without forking or breaking the core standard.

10. Under what license is the MAXGEN standard released? MAXGEN is released under a CC0 license, allowing anyone to adopt, build upon, or publish data using the standard, provided they credit the source.

Section 3: Comprehensive Glossary

Term Definition
AdditionalProperties A configuration in the schema where the core is "false" (closed) but the extensions are "true" (open), allowing for custom fields.
CC0 The Creative Commons Attribution license, which allows for the free sharing and adaptation of the standard with proper credit.
Centimorgans (cM) A unit of genetic measurement used in MaxDNA to describe the size of shared DNA segments between matches.
Confidence Score A numerical value (0.0 to 1.0) assigned to every assertion to represent its degree of certainty.
Consensus_group_id A field in MaxRecognition used to link multiple independent transcriptions of the same document image for aggregate confidence calculation.
DNA_evidence[] An array in MaxPerson that links genetic matches to relationship claims to boost confidence via noisy-OR combination.
Embedding_text A field in MaxSource containing metadata designed for vector database indexing and semantic search.
Extensions{} A dedicated object in every MAXGEN schema used to house platform-specific data while keeping the core schema valid.
GEDCOM The traditional genealogy interchange format (est. 1984) which MAXGEN aims to modernize.
HMAC-SHA-256 The cryptographic hashing algorithm used to secure kit identifiers in the MaxDNA schema.
Is_living A boolean flag used to trigger privacy gates; living people are automatically excluded from public endpoints.
MaxDNA The schema for genetic evidence, focusing on matches, segments, and haplogroups while excluding raw genotype data.
MaxName The schema that maps canonical names to their historical, linguistic, and orthographic variants.
MaxPerson The identity layer where probabilistic assertions about individuals are stored and linked to sources.
MaxRecognition The transcription layer that tracks the provenance and confidence of AI or human-generated text from document images.
MaxRecord The source layer representing raw, uninterpreted data exactly as it appears on a historical document.
MaxSource The discovery layer that catalogues record collections, including their coverage, access requirements, and location.
MaxTask The work layer used to dispatch, track, and record the results of genealogical research tasks.
MAXGEN A set of seven interoperable schemas designed for probabilistic genealogy and AI reasoning.
Noisy-OR A probabilistic combination method used to increase the confidence of a relationship claim when multiple pieces of evidence (e.g., DNA and documents) coexist.
OpenGenealogyAI The organization responsible for maintaining and developing the MAXGEN standard.
Probabilistic Identity An identity formed by a collection of assertions with varying confidence scores rather than a single definitive record.
Tier2-private A high-level privacy restriction in MAXGEN that prevents data from being shared on public endpoints; mandatory for all DNA records.
Verdict Vocabulary The structured result options in MaxTask, including key_finding, usable, inconclusive, ruled_out, dead_end, and infra.
