MaxSource: The Routing Brain of Genealogical Data

MaxSource is a specialized schema within the MAXGEN framework designed to solve the "Navigator’s Problem"—the difficulty researchers face in identifying which archives, databases, or portals contain specific genealogical records. Rather than acting as a database of the records themselves, MaxSource serves as a database of where those records reside, providing structured metadata that allows search engines to route researchers to the correct locations in milliseconds.

1. Core Functions and Structure

MaxSource transforms genealogical knowledge into a machine-readable format. Each record in the MaxSource schema describes a single source and its attributes, enabling automated systems to answer the question: "Where do I find X?"

Source Categorization

MaxSource recognizes twelve distinct source types. These types act as "routing signals," determining how a system interacts with the source (e.g., querying an API versus browsing a forum).

Source Type Description
directory_index Curated link lists (e.g., Cyndi’s List).
research_wiki Locality-based articles (e.g., FamilySearch Research Wiki).
record_catalog Catalogs of specific record collections.
record_database Searchable databases containing actual records.
archive Physical or digital repositories of primary sources.
dna_database Repositories for genetic genealogy data.
library Physical or digital bibliographic collections.
newspaper_archive Collections of historical news publications.
forum Message boards and community discussion sites.
blog Regularly updated informational websites.
society Organizations dedicated to genealogy or history.
other Miscellaneous sources not covered by the above.

The Coverage Object (coverage{})

The coverage{} object is the technical heart of a MaxSource record. it defines the scope of the source across several dimensions: * Geography: Mirrors the MaxRecord location structure (Country, State/Province, County/District, City/Town). * Record Types: Specifies what kind of records are available (e.g., death records, baptismal registers). * Time Period: Captured via year_min and year_max fields to ensure chronological relevance. * Demographics: Includes languages, ethnic groups, and religious affiliations (e.g., Lutheran, Reformed).

The Access Object (access{})

This object provides the technical requirements for interacting with a source. It includes the access_method (e.g., free_web, paid_subscription, api, onsite_only) and critical harvester information such as robots.txt status and crawl_notes. The crawl_notes field is particularly vital as it stores "institutional knowledge"—human-refined instructions to prevent harvesters from becoming "bad actors" by overloading servers or violating terms of service.

2. Advanced Search and Semantic Intelligence

Embedding Text and Semantic Search

The embedding_text field allows MaxSource to function as a semantic search engine. This field contains a denormalized, natural-language description of the source. When processed by a vector database, it enables the system to find records based on semantic similarity rather than simple keyword matching.

For example, a query for "Lutheran records in Württemberg" will return Archion not because of a keyword match, but because the semantic content of the Archion record—mentioning Protestant church books, baptisms, and German states—aligns with the query in a high-dimensional semantic space.

Provenance and Historical Integrity

The provenance{} object tracks the origin and reliability of the data. It records where a source was discovered, its current status (active, dead_link, superseded, or unverified), and when it was last verified. Notably, dead links are preserved to maintain a historical record of a source's existence.

Copyright and Redistribution

MaxSource explicitly addresses the legal complexities of ingesting proprietary catalogs (like Cyndi’s List). Through the redistribution_license field, entries can be marked as tier2-private. This allows an operator to use the data internally for routing while preventing it from being shared in public APIs or datasets, ensuring compliance with intellectual property rights.

Comprehensive Glossary

Schema Field Names

  • access{}: An object describing how to reach and interact with a source's data.
  • access_method: A field within the access object specifying the mode of entry (e.g., free_web, api, onsite_only).
  • asserted_at: The timestamp indicating when a source's information was claimed.
  • asserted_by: The entity or user who provided the information for the record.
  • coverage{}: The core object describing the geographic, temporal, and topical scope of a source.
  • crawl_notes: Human-readable nuances and instructions for programmatic harvesters to ensure respectful data collection.
  • discovered_via: A field in the provenance object identifying the "seed source" that led to the discovery of the current record.
  • embedding_text: A denormalized, natural-language description of a source used for vector-based semantic search.
  • external_ref: A specific link or article title from the seed source where the record was found.
  • last_verified_at: The date the source's accessibility and data were last confirmed.
  • redistribution_license: A field indicating the legal permissions for sharing the record's data.
  • status: The current state of the source (e.g., active, dead_link, superseded).
  • year_max: The end of the time period covered by a source.
  • year_min: The beginning of the time period covered by a source.

Genealogical Terms

  • Church Records: Documents maintained by religious institutions (e.g., baptisms, confirmations, marriages, burials).
  • Civil Registration: Government-maintained records of births, marriages, and deaths (in Germany, often beginning post-1876).
  • Emigration Records: Documents tracking the departure of individuals from their home country.
  • Primary Sources: Original records created at the time of an event (e.g., a contemporary baptismal entry).

Technical Concepts and Acronyms

  • API (Application Programming Interface): A machine-readable endpoint that allows different software systems to communicate and exchange data.
  • Dead Link: A URL that is no longer functional; MaxSource retains these for historical reference.
  • Harvester: An automated program (like a crawler or scraper) designed to collect data from websites.
  • MAXGEN: The overarching framework and system of which MaxSource is a component.
  • MaxRecord: The location structure mirrored by MaxSource to ensure data compatibility.
  • MaxSource: The specific schema designed to store metadata about genealogical sources to facilitate routing.
  • Robots.txt: A standard used by websites to communicate with web crawlers about which parts of the site should not be processed.
  • Semantic Search: A search method that understands the intent and contextual meaning of a query rather than just matching keywords.
  • Tier2-private: A licensing designation indicating data can be used for internal routing but cannot be shared publicly due to copyright concerns.
  • Vector Database: A database that stores data as mathematical vectors, allowing for high-speed semantic similarity searches.
