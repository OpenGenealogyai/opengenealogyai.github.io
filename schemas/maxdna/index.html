MAXGEN schema · v2.1

MaxDNA

One MaxDNA is one person's DNA test and its matches (always private).

Download MaxDNA (2.1) All versions https://opengenealogyai.org/schemas/maxgen/v2/dna.schema.json

SHA-256 dc96f9d4d08b8c484a8fb1ac5d8c7a6ae6ffb9e623817fc14b99d63567986bf7

Definition

MAXGEN 2.0 -- One MaxDNA document is one person's DNA test and its matches, always tier2-private, holding no raw genotype data and no raw kit number (only keyed fingerprints), with each match a claim that cites the saved match list.

The schema's own description, word for word.

Fields

The top-level fields of a MaxDNA document. Parts shared by every schema (the date block, the place block, the evidence link, the claim header and others) are defined once in the shared building-blocks file.

FieldTypeMeaning
dna_id requireduuidRandom id of this DNA test document, created once by its writer and never reused.
person_id requireduuidThe MaxPerson who took this test (the one top-level key MaxDNA shares with MaxPerson; the kind is decided by dna_id first).
test_type requiredenumType of DNA test: unknown when the source does not say (an imported DNA table may not), other with test_type_as_written.
test_type_as_written stringThe source's own words for the test type, written when test_type is other.
test_provider enumCompany or platform that performed or hosts the original test (other with test_provider_as_written).
test_provider_as_written stringThe source's own name for the provider, written when test_provider is other.
test_date dateWhen the test was taken, as a date block (a year alone is fine).
kit_id_status enumWhether the kit number's fingerprint is known: hashed (the default when left out) requires kit_id_hash; unknown when the source gave no kit number.
kit_id_hash sha256Keyed fingerprint (HMAC-SHA-256 keyed with the database's own secret kit_key, not a plain SHA-256) of the kit number, trimmed and upper-cased; the kit makes it with `maxgen_db.py kit-hash`; the raw kit number is never st
kit_source requiredstringWhere this test's details came from, in plain words (for example user_self_report, opensnp_public or an imported tree file).
haplogroup_y stringY-DNA haplogroup (paternal line) as the provider reported it, for example R-M269.
haplogroup_mt stringmtDNA haplogroup (maternal line) as the provider reported it, for example H1a1.
haplogroup_y_confidence confidenceThe provider's own confidence in the Y-DNA haplogroup, 0 to 1, kept as reported.
haplogroup_mt_confidence confidenceThe provider's own confidence in the mtDNA haplogroup, 0 to 1, kept as reported.
ancestry_composition array of ancestry_componentEthnicity or admixture estimates as the provider reported them; they add up to about 100 percent.
endogamy_flag booleanTrue if the test subject belongs to an endogamous population, where the usual shared-cM ranges are unreliable.
endogamy_population stringThe endogamous population, in plain words, when endogamy_flag is true.
matches array of matchThe matches reported for this test, each a claim citing the saved match list; a match between two tests in this database is stored once, on the test with the smaller dna_id (R-25).
kit_aliases array of kit_aliasThe same kit's ids at other services, as keyed fingerprints only (replaces the 1.x external_ids map).
is_living_flag requiredbooleanLiving A: true if the test subject may be alive, and true when unsure; a floor the kit only raises.
redistribution_license requiredlicenceAlways tier2-private: genetic data touches relatives who never agreed to share it, so no other value is accepted.
raw_genotype_stored requiredconst falseAlways false: MAXGEN never stores raw genotype data (FASTQ, VCF or raw SNP files); that stays with the provider or the person.
external_raw_data_location stringPlain words saying where the raw data is held (for example the person's own drive or the provider account); never a raw kit number, a genotype or an unhashed id.
consent_status requiredenumLegal basis for keeping this DNA data: the first four values are consent; withdrawn, pending, unknown (an import that does not say) and any value the kit does not know are read as not consented, so the test is shown only
consented_at timestampWhen consent was given.
consent_evidence_url uriAddress of the signed consent record, kept somewhere private.
withdrawal_requested_at timestampWhen the test subject asked for this DNA data to be withdrawn.
source_record_ids array of uuidMaxRecords that document this test (a saved provider page, a consent form, a lab report); replaces the 1.x source_records.

What changed from 1.13

The 1.13 fields are kept, always tier2-private. asserted_by and asserted_at removed; the top-level notes string replaced by the shared notes list; kit_id_hash optional with kit_id_status; test_date a date block; external_ids becomes kit_aliases; source_records becomes source_record_ids. Each match becomes a claim with a permanent match_id, its own is_living, and evidence citing the saved match list (a dna_match_list record, which the schema keeps living and tier2-private); predicted relationships keep the company's own words and probabilities. A match between two tests in one database is stored once. Kit numbers are never stored: their fingerprints are keyed with a secret only the person's own database holds.
