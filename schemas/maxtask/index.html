MAXGEN schema · v2.1

MaxTask

One MaxTask is one piece of work: research, an import, a review or a proof.

Download MaxTask (2.1) All versions https://opengenealogyai.org/schemas/maxgen/v2/task-queue.schema.json

SHA-256 0a5d2354506e81bc336cefe3b9af5c387fd5f4e83dc8b255f4e274586ecef457

Definition

MAXGEN 2.0 -- One MaxTask is the permanent record of one piece of work done in a database (research, an import, a review or a proof), never pruned while anything points at it.

The schema's own description, word for word.

Fields

The top-level fields of a MaxTask document. Parts shared by every schema (the date block, the place block, the evidence link, the claim header and others) are defined once in the shared building-blocks file.

FieldTypeMeaning
task_id requireduuidThis task's own id: a random UUID created once by the writer and never reused.
task_type requiredenumWhat kind of work this is; a task of type other permits none of the gated actions of rules R-24, R-28 and R-31.
task_type_as_written stringThe kind of work in the writer's own words, given when task_type is other.
status requiredenumWhere the work stands, changed only through the helper's task command (pending, processing, then done, failed or escalated; on_hold pauses it; a task made by mistake or retracted is cancelled, never deleted).
priority integerHow urgent the task is, from 1 (lowest) to 10 (highest).
payload objectThe task's input, an open object whose documented kinds are interview, person_request, person_page_session, fan_survey (person_id), run (run_id, on a judge_review task), find_original (record_id), import_file (format: ge
result resultWhat the work found and decided, in a closed, readable shape.
provenance provenanceHelper-owned and written once: who did the work of this task, filled when the task is first claimed (moved to processing) or created already done.
created_by stringThe agent id of the session that wrote this task: optional in input, filled by the helper from the writing session, required in stored form, and a different value is refused (R-14).
started_at timestampHelper-owned: when the task was first moved to processing.
completed_at timestampHelper-owned: when the task reached done, failed or cancelled.
is_living_flag requiredbooleanLiving A floor: true when the task names or concerns someone who may be alive (unsure means true); it only rises, and while it is true the task must be first_party_only.
contributor_eligibility enumWho may be given this task: first_party_only (the person's own kit and agents, the default, failing closed) or any_contributor; it must be first_party_only whenever is_living_flag is true.
assigned_to stringThe agent id now working on this task; absent while it is pending.
cost_usd numberWhat the work actually cost, in US dollars.
cost_cap_usd numberThe most this task may cost, in US dollars; the agent stops and escalates before going over it.
retry_count integerHow many times the task has been retried after a failure.
max_retries integerHow many retries are allowed before the task is left failed.
error_message stringWhat went wrong, when the task failed or was escalated.
escalation_reason stringWhy the task was escalated for a further decision.
queue_file_path stringThe task's path in a file-based queue on this computer; private, never exported.
depends_on array of uuidTasks that must be done before this one can start.
parent_task_id uuidThe task that made this task (on MaxTask this replaces created_by_task_id, which tasks may not carry).
acceptance_criteria array of stringPlain, checkable conditions that a complete result must meet.
min_confidence confidenceThe lowest result confidence that can be accepted.
evidence_required array of stringWhat the worker must hand back as proof of the work (addresses, exact queries, records saved).
deadline timestampWhen the work should be finished.

Refused by name: created_by_task_id. A document that contains this field is not valid.

Added in 2.1

2.1 only adds; every 2.0 MaxTask stays valid. In the schema file's own words:

  • payload.kind (description updated): Which documented payload this is: interview, person_request, person_page_session, fan_survey, run, find_original, import_file, analysis, or (G-04, additive) incoming_finding: one finding from another tree (a relative's file as suggestions, a findings delivery), holding its proposed facts and any proposed new person in the payload (sender_tree_id, sender_label, received_at, verdict, person_id or new_person and relation, facts) until the person lets it in; it is never a claim on the person's people while it waits.

Everything 2.1 added

What changed from 1.13

Removed: contributor (now provenance, written once by the kit), the top-level review (reviews are now separate judge_review tasks, never overwritten), a required created_at (now kit-owned). Added: provenance, is_living_flag (required), statuses on_hold and cancelled, task types find_original and import_file, the verdict inaccessible (could not search; never a dead end), and a closed result holding the search steps (the only search log), a proof write-up (the single authority for "proven"), occurrence verdicts, reviews, run decisions and FAN-club associates (the friends, associates and neighbours studied around one person). A proof's parent-set changes can set a set's kind, make it the main set, add a parent's existing link to it, or retract it.
