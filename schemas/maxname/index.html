MAXGEN schema · v2.1

MaxName

One MaxName is knowledge about one name.

Download MaxName (2.1) All versions https://opengenealogyai.org/schemas/maxgen/v2/name.schema.json

SHA-256 521b1b28cfba2a121e40a9bb71b08982aa3bacba0d39a62907088c40606bacb1

Definition

MAXGEN 2.0 -- One MaxName is what is known about one name: its canonical form, its variants and cross-language cognates (each citing evidence and carrying the claim status ladder), and its phonetic keys.

The schema's own description, word for word.

Fields

The top-level fields of a MaxName document. Parts shared by every schema (the date block, the place block, the evidence link, the claim header and others) are defined once in the shared building-blocks file.

FieldTypeMeaning
name_id requireduuidThis name record's own id: a random UUID created once by the writer and never reused.
canonical_form requiredstringThe modern standard spelling used as the anchor for every variant (such as the made-up surname Quillfeather), not necessarily English.
canonical_script scriptThe writing system of canonical_form.
canonical_script_as_written stringThe writing system in the writer's own words, given when canonical_script is other.
regional_canonical array of objectPreferred forms of the name in other languages or regions, so no one language is the anchor.
name_type requiredenumWhat kind of name this is: given, surname, patronymic, matronymic, occupational, topographic, clan, byname, religious, title or other.
name_type_as_written stringThe kind of name in the writer's own words, given when name_type is other.
gender enumThe gender the name is associated with in its own culture (a cultural association, never a statement about any person).
gender_as_written stringThe association in the writer's own words, given when gender is other.
language_of_origin stringThe language the name ultimately comes from, as an ISO 639-3 code.
etymology stringWhere the name comes from and what it meant, written for a general reader.
see_also_urls array of stringAddresses of reference works about the name.
variants array of variantEvery known variant form; each is its own claim with evidence, retracted rather than deleted.
phonetic_keys objectPhonetic codes of the canonical form for fuzzy search, each with the algorithm version that made it so indexes rebuilt later do not mismatch silently.
cognates array of cognateRelated names in other languages; a first pass may name the target only by related_canonical_form and a later linking pass adds related_name_id.
redistribution_license requiredlicenceWhether this name record may be shared (unclear means ask, never guess).

What changed from 1.13

The 1.13 shape is kept. contributor is removed (the task's provenance replaces it). Every variant and cognate becomes a claim, with a kit-owned assertion_id, a status and a required evidence link and confidence. Lifecycle fields added; redistribution_license required.
